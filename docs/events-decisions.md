# v0 event and metric decisions

`share_asset_generated` is emitted only after the share canvas has completed and the resulting asset is visible. Its distinct-person count divided by distinct successful card recipients is the active **save upper bound**. It does not claim that the asset was saved. There is deliberately no download-success event. `share_asset_download_triggered` means a non-WeChat download was initiated, while `share_longpress_hint_shown` means the WeChat save prompt was displayed. Neither proves a save.

`share_intent` is separate. Opening a panel or invoking a share control is an intent signal, not completed sharing. The v3 active-share threshold (pass at 25%, improve below 15%) remains in configuration as `superseded_inactive` for audit and is not silently attached to a replacement event.

`shared_link_opened` is the main dissemination measure. It can enter analytics only through `acceptSharedLinkOpen`, a trusted call boundary used by the server adapter after that adapter verifies the referral reference. Evidence and `trust` values must be stripped from HTTP payloads; they are never accepted as client credentials or passed through to this boundary. A client field such as `source=server` has no authority. Visitors are deduplicated by anonymous ID, creator self-visits and references to unknown creators are excluded, and first touch wins. Absolute timestamp order is used; if timestamps tie, lexical event ID order makes attribution deterministic. The global rate is distinct attributed visitors divided by distinct successful creators; per-creator counts are returned for diagnosis.

Only the explicit aggregate records `ip_pollution_window_flagged` and `ip_pollution_after_exhaustion` are excluded from metric numerators and denominators. They enter through the server-only `acceptIpPollutionEvent` boundary after salted-IP aggregation; clients cannot submit them, and this module does not implement the later-stage aggregator. A `pollution` tag never removes a person's legitimate creation, save-upper-bound, repeat, or referral actions. Aggregate pollution records carry only a window length and distinct count. No raw IP or IP-derived hash is stored in event data or metrics.

`generation_refunded` means a terminal failure returned one free attempt. It is not a paid refund and v0 has no payment or account ledger. `generation_restored` means the original task was restored with the same draw; it is not a newly purchased entitlement.

`generation_requested.reason` distinguishes `initial`, `new`, `quality_repair`, and `retry`. Only `new` contributes to repeat generation, and only when its absolute timestamp follows a successfully issued card for that person. Automatic collection is not saving. `card_generated` records successful delivery; distinct `valid_input_submitted` actors form the completion denominator, and `input_rejected` remains separately reportable. Structured QA events can carry a bounded outcome and hard-veto category without free-form text.

The event schema accepts only documented fields. Raw IP, photos, names, free-form notes, and other undeclared keys are rejected. The CSV and metrics validators are pure and accept their source data as arguments, so startup code can fail closed without filesystem access in the domain module.
