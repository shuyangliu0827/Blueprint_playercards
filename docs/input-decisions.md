# 输入、姿势与故事的实现决定

本文只记录 v0 输入模块的工程解释。产品规则来自 v3 文档和已确认修正，不把已确认规则标成占位值。

## 已确认规则的落实

- 照片只接受 JPEG、PNG、HEIC。浏览器负责转码与方向纠正；核心层只消费纠正后的元数据和人脸检测结果，不加载检测库。
- 文件硬上限采用十进制 `10,000,000` 字节。短边低于 `1024` 像素只产生提示，不阻止继续。
- 检测不到人脸是硬错误。检测到多人时必须提供从零开始且在范围内的主体索引。
- 照片、昵称、号码、位置、惯用手五项必填。惯用手没有默认值。
- 人脸处理单独同意、照片使用权确认、年满 18 周岁本人声明是三个独立的布尔声明，均须明确为真。公开分享与训练授权不由这些声明推导。
- 昵称在去首尾空格并做 NFKC 后校验：纯汉字 1–6 个 Unicode 字符，纯拉丁名字 1–14 个 Unicode 字符；拉丁名字可含单个常用分隔符。
- 号码以字符串保存，接受 `0`–`99` 的一位或两位数字，因此 `00`、`07` 会原样保留。
- 姿势路由严格为位置组 G/F/C 与角度 F/L/R 的九种组合。不确定角度归 F。姿势素材以右手为规范，左手输入返回 `mirror: true`；镜像不增加 poseId。
- 卡背故事由 2–3 个配置句子拼接，总长不超过 80 个 Unicode 字符；只代入昵称、号码与位置，不生成球队、成绩、签名或统计事实。

## 工程选择

- MIME 上限采用文档列出的三个值，不额外接受 WebP 或 `image/heif`。平台适配层可在进入核心校验前把等价平台标识映射为这里的规范值。
- 昵称分隔符允许空格、点、下划线、直引号、弯引号和连字符。姓名禁用匹配会把这些分隔符统一成一个空格，再做完整别名相等比较；不做子串匹配，因此禁用 `James` 不会误伤 `Jameson`。
- `player_names.json` 是独立、可增量维护的静态禁用词库，只覆盖部分 NBA 现役与知名退役球员的中英文常用名和别名。它不宣称完整，也不宣称实时更新。
- 四个公开配置校验器接收 `unknown` 并在字段缺失、字段多余、类型错误或确认值被改变时抛错，供统一启动检查直接调用。

## 模块边界

核心文件不读取文件、环境变量、浏览器 API、外部服务或存储。调用方负责加载 JSON、完成图片方向纠正、人脸数量与角度检测，再将结构化结果传入纯函数。
