# v3 原型交付记录

## 范围与优先级
本次只采用 v3 业务规则和用户五项更正。用户最后授权连续交付第二、三批、独立决定并记录缺失参数、复用此前视觉模板；据此取消分批确认等待。

第一批：纯抽取与 HMAC seed、五档配置、概率与数量启动校验、版本指纹、姿势路由、输入校验、姓名词库、文案模板与埋点口径。
第二批：5:7 配置化正反面、五档 WebGL1 材质、静态反光降级、平台适配层、四种客户端导出、200px 中心裁切调试页。
第三批：移动 H5、浏览器本地人脸检测与 HEIC 转换、异步 Mock 流程、成功次数与失败恢复、埋点/分享回流、私有源码仓库与 Vercel 预览。

## 自主推荐与代价
1. 视觉复用 BLUEPRINT 深色球场、细金属卡框、大字昵称；旧球队、稀缺编号、支付或早期概率没有带入。三张旧生成画面仅作为示例。若设计师改变方向，仅替换资产和配置。
2. layout/effect 根级 `_placeholder: true` 说明整份是工程设计初版。画布1500×2100为确认值；300 DPI、字号、遮罩、响应曲线、低帧率阈值是可替换的推荐值。设计师调整 schema 时同步验证器与配置；不影响抽取/输入/埋点核心。
3. 系统字体避免外部字体请求与新授权依赖；不同操作系统字形略有差别，后续可通过 font.source 交付本地授权字体。
4. 本地 MediaPipe 人脸检测用于硬门槛和粗略脸角度。CPU 模式、0.4 检出阈值、最长边2048处理；照片实际短边1024只提示，不拦截。无外部推理调用。侧脸判别是粗略路由，不是身份或生物识别认证。
5. Mock 仅使用人形轮廓、球、照片裁出的头像，明确显示 poseId/mirror。镜像作用于身体，保留脸部原方向。没有真实图像模型、质量判别模型或效果承诺。
6. 正常延迟按连续分布的中位12秒、95分位40秒模拟；评审设置提供0.5秒、必成功、单次重试、终态失败。失败恢复不重新抽材质。
7. 异步接口用轮询推进内存状态，没有依赖 Serverless 长驻计时器。Vercel 多实例/重启可能丢失次数、任务和统计；HMAC 抽取在同密钥及固定配置下不变。客户端遇到任务过期按原 requestId 恢复。
8. 分享缩略图1000×800；对比图2400×1600，只在点击后生成；分享海报1080×1440中卡片790×1106，占60.2%。二维码用当前域名+签名ref，不硬编码部署域名。
9. 图片嵌入300 DPI与PNG iTXt合成来源说明；它是内部预览元数据，不声称是平台认证或完整生产合规实现。
10. 无WebGL、上下文丢失或连续低帧率改用预渲染透明PNG。静态图来自同一着色器，不含照片文字；因此降级仍保留卡面可读性。
11. 保存指标在图片真正呈现后触发 share_asset_generated；它只是保存上界。下载点击与微信长按提示分别记录，不使用“下载成功”。主传播指标来自签名ref的服务端去重访客。
12. 内部数据面板仅返回自己的事件与归因回流；不把IP哈希下发，不排除被标记的用户行为。所有事件与任务均无外部存储。

## 已验证与边界
- 配置验证、严格类型检查、单元测试及生产构建。
- 桌面/390px移动端：本地识脸→提交→自动重试→正反面→四种导出；失败返还→原结果恢复；独立访客ref去重。
- 网络观察没有照片内容上传或外部资源/推理请求。
- 四种PNG像素尺寸、300 DPI、合成标识；海报二维码实际解码通过。
- 五档静态切换与动态恢复、无WebGL降级；小图中心裁切评审。
- 浏览器自动化基于Chrome；未使用真实微信iOS/Android设备。本次不声称完成微信真机性能、HEIC机型矩阵或正式模型质量评测。
- 设计、姿势动作和生成质量仍是原型阶段；没有未决问题阻止使用当前内部预览。

可复现检查：npm run check；npm run build；启动后运行 scripts/e2e.mjs、scripts/render-regressions.mjs、scripts/check-exports.mjs。线上可通过 TEST_URL 指向部署地址重复。

线上复测补充：签名匿名cookie跨进程仍有效；API现在会在新进程重建该匿名身份，避免统计读取因为本地身份缺失而直接报错。此操作不会恢复已丢失的内存事件/次数。导出埋点为异步发送，自动化验收等待服务端实际接收后再检查数量。
