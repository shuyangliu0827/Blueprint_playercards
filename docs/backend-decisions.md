# v0 preview backend decisions

The preview API uses one App Router endpoint and one process-global `PreviewService`. State is intentionally memory-only: deployment restarts can expire sessions, jobs, referral deduplication, and analytics. A missing job returns `TASK_EXPIRED`; the browser may submit the same immutable request ID again and receives the same HMAC-derived draw.

Quota is reserved when a valid job is accepted, so concurrent requests cannot exceed three potential successful cards. A reservation becomes a successful issuance only after `complete`, and is released on terminal generation or render failure. Retry and restore retain the original draw. Restore is an operational recovery and does not create a second `generation_requested` event.

The service never receives image bytes. `photo` is a strict metadata object containing only MIME type, size, width, and height; request bodies are capped at 20 KB. Job state retains pose and draw metadata but no nickname or image metadata. Analytics pass through the existing event validators, client actor IDs are replaced with the signed-cookie identity, trusted event names cannot cross the client boundary, and generation lifecycle events are emitted by the service.

Anonymous cookies and referral tokens use HMAC-SHA256. `DRAW_HMAC_SECRET` and `IP_HASH_SALT` must each contain at least 32 UTF-8 bytes. Cookies are HTTP-only, SameSite=Lax, and Secure in production. Referral opens require a valid signed token and are deduplicated by visitor; self-opens are excluded. A signature remains authoritative when the creator identity originated on another Vercel instance. Referral-rate denominators remain limited to successful recipients visible in the current process.

Only a salted HMAC aggregation key is retained for IP checks. No raw IP or IP hash enters events or API output. The route accepts the first `x-forwarded-for` value because Vercel overwrites that header at its trusted edge; a different hosting adapter must establish its own trusted-proxy boundary before forwarding an address. Pollution signals are record-only and never block users or remove them from metrics.

Jobs, events, identities, completion tombstones, referrals, and IP windows have count bounds. Events expire by server receipt time, never by caller timestamps. A queue at its active-job bound evicts finished full-job records first and rejects new work with `QUEUE_BUSY` only when every slot is active. An untouched reservation expires after 30 minutes, releases quota, and leaves its original draw available for restore. Identity success counters and compact tombstones do not expire on an ordinary idle timer; they survive until process loss or bounded LRU pressure. Such LRU eviction is an accepted memory-only reset in v0. This process-local design is suitable only for the internal preview; durable production issuance needs shared persistence and server-authoritative first-success state.

Failure ratios and normal/fast latency parameters are read from `generation_contract.json`, validated at service construction, and used by the mock state machine. The same contract declares the future generator method shape, async transport, return category, and manual QA hook; a real generator remains outside v0 scope.
